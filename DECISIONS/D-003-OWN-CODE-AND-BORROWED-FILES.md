# D-003 — Своё приложение; из AOSP DeskClock — только отдельные файлы

- **Статус:** Accepted
- **Дата:** 2026-10-19
- **Область:** основа продукта, лицензии, происхождение кода

## Контекст

Первые документы брали AOSP DeskClock исходной точкой: обсуждались форк, правка системного DeskClock в ROM и импорт всего upstream-проекта в `/reference` (workflow `vendor-aosp-deskclock.yml`; оба его запуска упали, импорт не состоялся). Позиция автора: чужой проект не копируется; заимствовать можно настолько, насколько позволяет лицензия.

Факты на 19 октября 2026 — по временному клону upstream `main`, коммит `04e481f37e0b` от 27 февраля 2025; клон удалён, в репозиторий ничего не перенесено. Подробно — [исследование AOSP DeskClock](../docs/RESEARCH/INITIAL_INVESTIGATION.md).

- `Android.bp` объявляет для модуля лицензию `Android-Apache-2.0`; у всех 172 файлов кода (`.kt`, `.java`) — заголовок Apache License 2.0.
- Apache 2.0 разрешает копировать, изменять, распространять и продавать, в том числе с закрытым кодом своей версии. Условия: приложить текст лицензии, сохранить уведомления об авторских правах, пометить изменённые файлы; права на товарные знаки лицензия не даёт (разделы 4 и 6).
- README upstream: приложение не поддерживается, исходник оставлен только как справка и будет убран из манифеста AOSP.
- У шрифта, звуков, изображений и 14 из 376 XML в `res/` заголовка лицензии нет; в метаданных шрифта — «Copyright 2016 Google Inc. All Rights Reserved.» без лицензии.
- Сборка — только Soong (`Android.bp`), `minSdkVersion` 23, `targetSdkVersion` 30.

## Варианты

1. Форк AOSP DeskClock — взять код целиком.
2. Правка системного DeskClock в собственной ROM.
3. Своё приложение с нуля; AOSP — только для сравнения.
4. Своё приложение; отдельные файлы AOSP — там, где экономят работу, по Apache 2.0.

## Решение

Выбран вариант 4 (автор, 19 октября 2026).

1. DP_Clock — самостоятельное приложение: архитектура, модель данных, интерфейс и сборка свои. Это не форк и не модификация системного DeskClock. Upstream-проект целиком в репозиторий не копируется — ни в `/reference`, ни куда-либо ещё.
2. Отдельный файл AOSP DeskClock (`platform/packages/apps/DeskClock`) можно взять, если он экономит работу и встраивается в архитектуру DP_Clock. Условия:
   - в самом файле есть заголовок Apache License 2.0;
   - заголовок с уведомлением об авторских правах сохраняется, под ним добавляется отметка об изменениях в DP_Clock;
   - файл записывается в [docs/PROVENANCE.md](../docs/PROVENANCE.md): путь здесь, путь и коммит upstream, дата, что изменено;
   - с первым заимствованным файлом в репозиторий кладётся текст Apache License 2.0, а до первой сборки для распространения приложение показывает лицензию и уведомления.
3. Не заимствуются:
   - файлы без заголовка лицензии в самом файле — шрифты, звуки, изображения, XML без заголовка;
   - что-либо из приложений с закрытым кодом или без разрешающей лицензии, в том числе из часов Google; такие приложения — только для фактического сравнения возможностей;
   - товарные знаки «Android» и Google в названии и оформлении, пакет `com.android.deskclock`.

## Аргументы

- Лицензия разрешает заимствование, включая продажу и закрытый код своей версии.
- Целиком upstream основой не подходит: он брошен, собирается только в дереве AOSP, у него старый `targetSdk`, а задуманная модель (единая модель расписаний, типизированные операции, необязательный ИИ — D-002) с ним не совпадает.
- Отдельные файлы могут сэкономить работу там, где задача платформенная и давно решена.
- Заголовок лицензии в самом файле — проверяемый признак: у шрифта, звуков и изображений его нет, и их лицензия неочевидна.

## Последствия

- Workflow `vendor-aosp-deskclock.yml` и `docs/RESEARCH/REFERENCE_SNAPSHOT.md` удалены.
- Открытое решение «самостоятельный APK, форк AOSP или изменение DeskClock в ROM» сужено до формата поставки своего приложения: самостоятельный APK и/или включение в собственную ROM.
- Исследование AOSP DeskClock — отбор файлов для заимствования и сравнение возможностей, а не инвентаризация основы.
- Перед продажей заимствования и уведомления проверяются юридически (ROADMAP, P4).

## Условия пересмотра

- Изменятся лицензия или доступность upstream.
- Заимствований станет столько, что DP_Clock фактически превратится в форк: тогда решение пересматривается явно, а не постепенно.
