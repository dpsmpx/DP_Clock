# D-005 — Отладочные сборки: ветка debug-builds и общий отладочный ключ

- **Статус:** Accepted
- **Дата:** 2026-10-19
- **Область:** сборка, подпись, распространение отладочных APK

## Контекст

Поручение автора (19 октября 2026): все отладочные сборки выкладываются в одну ветку, файл называется `"debug-" + commit_name + ".apk"`. Имя ветки «debug builds» с пробелом Git не допускает. Облачная сессия при каждом запуске создаёт свой отладочный ключ, а сборку, подписанную другим ключом, Android поверх прежней не ставит.

## Варианты

- Ветка: `debug-builds`, `debug_builds` или `debug/builds`.
- `commit_name`: короткий SHA, полный SHA или заголовок коммита.
- Подпись: общий отладочный ключ в репозитории или ключ каждой сессии.

## Решение

Выбор автора формой опроса, 19 октября 2026.

1. Ветка `debug-builds` — без истории `main`, в ней только APK. Каждая сборка — новый коммит поверх прежних; все файлы остаются в ветке. В `main` ветка не вливается.
2. Файл — `debug-<короткий SHA>.apk`. Собирается только закоммиченное дерево: иначе SHA не описывал бы содержимое APK. В сообщении коммита — полный SHA исходного коммита, его заголовок, версия и SHA-256 файла.
3. Собирает и выкладывает `tools/debug-apk.sh --publish`; порядок — [docs/DEVELOPMENT/BUILD.md](../docs/DEVELOPMENT/BUILD.md).
4. Отладочные сборки подписаны общим ключом `app/debug.keystore` (пароль `android`) из репозитория, поэтому каждая следующая ставится поверх предыдущей. Это не секрет и не ключ выпуска; ключ выпуска в репозиторий не попадает.

## Аргументы

- Одна ветка — одно место, откуда автор берёт сборки; история `main` в ней не нужна.
- Короткий SHA уникален, короток и сразу указывает на коммит, из которого собрано.
- Общий ключ избавляет от удаления приложения перед каждой новой сборкой. Риск: имеющий доступ к репозиторию может подписать отладочную сборку, которая встанет поверх. Для закрытого репозитория и отладочных сборок это приемлемо.

## Условия пересмотра

- Репозиторий станет открытым или отладочные сборки начнут получать не только автор — ключ заменяется и выносится из репозитория.
- Размер ветки станет мешать — старые сборки убираются отдельным решением.
