# D-009 — Модель данных, хранение и модули

- **Статус:** Accepted
- **Дата:** 2026-10-19
- **Область:** данные, хранение, миграции, устройство кода

## Контекст

Этап P0: модель данных для MVP (D-006) с заделом под версию 1.0 (D-007) и механизмами платформы D-008 — хранилище устройства, моменты времени, пересчёт будильников. Модель — [DATA_MODEL.md](../docs/ARCHITECTURE/DATA_MODEL.md).

## Варианты

- Хранение: Room (SQLite), SQLite без библиотеки, файл JSON.
- Идентификаторы: числа по порядку или UUID.
- Правила времени: в приложении Android или в отдельном модуле на чистом Kotlin.

## Решение

1. **Модель** — по [DATA_MODEL.md](../docs/ARCHITECTURE/DATA_MODEL.md). Время будильника — местное и следует за часовым поясом. Моменты — UTC. Длительности — по монотонным часам, с моментом UTC на случай перезагрузки.
2. **Особые случаи времени:** пропущенное при переходе на летнее время — сигнал в первый существующий момент; повторившееся при переходе на зимнее — один сигнал, в первое наступление. Опоздание больше 10 минут — не звонить, показать пропуск.
3. **Идентификаторы** — UUID.
4. **Хранение** — одна база Room в хранилище устройства (D-008). Схема версионируется с первой сборки с базой; каждая новая версия — миграция с тестом. Тесты базы идут на JVM со встроенным SQLite, без эмулятора.
5. **Модули:** правила времени и модель — Gradle-модуль на чистом Kotlin без Android (`:core:model`), с unit-тестами на граничных датах и поясах. Хранение, будильники Android и интерфейс — в модулях Android.
6. **Журнал срабатываний** — только на устройстве, последние 1000 событий: основа статистики 1.0 и проверки опозданий на телефоне. С 0.12.1 хранится весь журнал — выбор автора для статистики ([D-023](D-023-CALENDAR-AND-STATISTICS.md), п. 7).

## Аргументы

- SQL-база выдерживает рост 1.0 — статистику, синхронизацию, сменные графики — без смены хранилища; Room проверяет запросы при сборке, а его миграции тестируются на JVM.
- UUID не придётся менять, когда появится синхронизация устройств.
- Правила времени без Android тестируются быстро и полностью — это главный риск продукта (принцип ARCHITECTURE «тестируемость правил времени независимо от UI»).
- Хранилище устройства — условие сигнала до разблокировки после перезагрузки (D-008).

## Последствия

- Новые зависимости — Room, встроенный SQLite для тестов, плагин KSP — добавляются вместе со строками в `docs/PROVENANCE.md` (D-003, п. 5), когда появится код.
- Совместимость Room и KSP со сборкой AGP 9 проверяется первой сборкой с базой. Если они не уживутся — SQLite без библиотеки, с той же схемой и теми же тестами миграций.
- `data_extraction_rules.xml` включит базу в системную копию одновременно с её появлением (D-006, п. 9).

## Пересмотр

- Объём или запросы статистики перерастут SQLite на телефоне.
- Синхронизация устройств (отдельное решение по D-007) потребует другой формы данных.
