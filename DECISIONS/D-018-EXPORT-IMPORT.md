# D-018 — Экспорт и импорт файлом: версия 0.7.0

- **Статус:** Proposed — код есть, выбор автора сделан; принимается после проверки на Redmi Note 13 (П1–П5 в [плане](../docs/QUALITY/DEVICE_TEST_PLAN.md))
- **Дата:** 2026-10-24
- **Область:** версия 1.0, [D-007](D-007-VERSION-1.0-SCOPE.md) — «резервная копия: системная, а также экспорт и импорт файлом»

## Контекст

Третий шаг захода после [D-016](D-016-TIMER-ADDITIONS.md) и [D-017](D-017-SLEEP-AND-WAKE.md). Системная копия (D-006) переносит базу целиком, но только через аккаунт Google и только при восстановлении. Файл нужен, чтобы перенести настройку самому: на другой телефон, после сброса, с одного телефона на второй. Автор ответил формой опроса 24 октября 2026: при загрузке спросить — добавить к имеющимся или заменить всё.

## Варианты

- Загрузка: всегда добавлять; всегда заменять; спрашивать при загрузке.
- Формат: JSON; своя текстовая строка, как у шаблонов (D-014); копия базы SQLite.

## Решение

1. **Версия** — `versionName` 0.7.0, `versionCode` 8.
2. **Что в файле:**
   - будильники со всеми полями — повтором, звуком, проверкой пробуждения и её образцом, мягким пробуждением, действиями после;
   - группы, шаблоны, исключения, пресеты таймеров, настройки.

   Не переносится то, что относится к телефону: идущие таймеры, секундомер, ожидающие срабатывания и «Отложить», журнал срабатываний, отметка «настроил Xiaomi».
3. **Формат** — JSON в UTF-8, файл `dp-clock-ГГГГ-ММ-ДД.json`:
   - в начале `"app": "DP_Clock"`, `"format": 1`, версия приложения и время сохранения, дальше списки;
   - поля названы по-английски, как в модели; дни недели и перечисления записаны именами, даты — в ISO; файл можно прочитать глазами.

   Правила чтения:
   - нет поля — значение по умолчанию;
   - неизвестное поле пропускается;
   - неизвестное значение перечисления или звук заменяются значением по умолчанию.

   Поэтому файл, сохранённый более новой версией приложения в формате 1, читается старой. Номер формата растёт, только если старая версия прочтёт файл неверно. Тогда она отказывается его загружать: «Файл из более новой версии».

   Разбор JSON свой, в `:core:model`, около 200 строк, без библиотеки. Им же читаются схемы Room в тесте миграций.
4. **Загрузка** (выбор автора — спросить). После выбора файла приложение показывает, что в нём («Будильники: 5», «Группы: 2», …), и предлагает:
   - «Добавить к имеющимся» (выбрано сначала): ничего не удаляется. Совпадения не ищутся: будильник, который уже есть, окажется дважды;
   - «Заменить всё»: сначала удаляются будильники, группы, шаблоны, исключения и пресеты. Звонящий сейчас будильник остаётся.

   Флажок «Взять настройки из файла» по умолчанию включён. Загруженному всегда даются новые id. Ссылки будильников на группы и пресеты из файла переводятся на новые id, ссылки на то, чего в файле нет, снимаются. Затем все расписания пересчитываются, как после загрузки телефона: прошедший однократный будильник «на дату» выключается.
5. **Ошибки.** Файл сначала разбирается целиком и только потом записывается в базу, поэтому при ошибке ничего не меняется. Сообщения:
   - «Это не файл DP Clock»;
   - «Файл из более новой версии»;
   - «Файл повреждён» (час 25, конец периода раньше начала и т. п.);
   - «Файл слишком большой» (больше 4 МБ);
   - «Файл не открывается».
6. **Где** — в настройках, раздел «Перенос»: «Сохранить в файл» и «Загрузить из файла». Файл выбирается в системном окне, разрешение на память телефона не нужно. При загрузке в окне видны файлы любого типа: мессенджеры и файловые менеджеры помечают JSON по-разному, а содержимое всё равно проверяется.
7. **Звуки и приложения на другом телефоне.**
   - Мелодия телефона берётся по адресу на том телефоне: она может оказаться другой или не найтись.
   - Свой аудиофайл не откроется: доступ к нему выдан только старому телефону.

   В обоих случаях, если звук не открылся, звучит звук DP_Clock (D-013, п. 2). Приложение «после будильника» ищется по имени пакета; если его нет, ничего не открывается.

## Аргументы

- Спрашивать при загрузке — выбор автора: «Добавить» не теряет имеющееся, «Заменить всё» подходит для переезда на новый телефон.
- JSON читается глазами и другими программами. Копия базы SQLite зависела бы от схемы и не позволила бы добавлять к имеющемуся.
- Новые id дают один путь для обоих способов загрузки, и связи не портятся, если тот же файл загрузить дважды.

## Последствия

- План проверки на устройстве: П1–П5.
- Файл не шифруется и лежит там, куда его сохранил человек. Названия, тексты напоминаний, образцы QR-кода и снимка места видны любому, у кого есть файл ([PRIVACY](../docs/SECURITY/PRIVACY_AND_API_KEYS.md)).

## Пересмотр

- Автор захочет, чтобы «Добавить» пропускало совпадающие будильники, — добавится сравнение.
- Понадобится перенос между DP_Clock и другими часами — это отдельное решение.
