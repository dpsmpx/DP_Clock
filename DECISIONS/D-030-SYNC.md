# D-030 — Синхронизация общим файлом в облаке — версия 0.17.0

- **Статус:** Accepted — выбор автора 31 октября 2026; общий файл вместо папки — из-за Google Диска, автору сказано до работы; на телефонах ещё не проверено (Ф1–Ф8 в [плане](../docs/QUALITY/DEVICE_TEST_PLAN.md))
- **Дата:** 2026-10-31
- **Область:** P4 [ROADMAP](../ROADMAP/ROADMAP.md) — синхронизация устройств; уточняет [D-028](D-028-SYNC-AND-TASKS-DIRECTION.md), п. 1; экран — [SCREEN_MAP](../docs/PRODUCT_CONCEPTS/SCREEN_MAP.md), раздел 18.

## Контекст

D-028 выбрал синхронизацию файлом в облачной папке, а что сливать и как часто — оставил до реализации. Автор ответил формой опроса 31 октября 2026:
- **что** — всё: будильники и группы, шаблоны и исключения, пресеты таймеров, настройки и мировые часы;
- **когда** — само: записать примерно через минуту после правки, прочитать при открытии приложения и раз в час, плюс кнопка «Сейчас»;
- **расхождение** — одно и то же поправили на двух телефонах — спрашивать;
- **включение** — своё у телефона: список и правки общие, включён ли будильник и пропуск — у каждого свои; новый будильник с другого телефона приходит выключенным.

Google Диск не даёт приложениям выбрать в нём папку целиком: системное окно выбора папки (Storage Access Framework, ACTION_OPEN_DOCUMENT_TREE) его не показывает. Файл — создать или открыть — Диск даёт.

## Решение

1. **Один общий файл вместо папки.** На первом телефоне человек создаёт файл `dp-clock-sync.json` системным окном — на Google Диске или в другом облаке. На других телефонах выбирает тот же файл. Приложение получает постоянное разрешение читать и писать только его. Каждый телефон читает файл, сливает со своей базой и записывает слитое обратно.
   - Своего сервера, входа в аккаунт и разрешения на сеть нет — как в D-028: с облаком связывается его приложение. Для задания «раз в час при любой сети» нужно обычное разрешение `ACCESS_NETWORK_STATE`: без него Android 14+ задание с условием сети не ставит. Окна с вопросом оно не показывает и ничего никуда не отправляет.
2. **Что синхронизируется** — то же, что в файле переноса (D-018), по записям: каждый будильник, группа, шаблон, исключение и пресет — отдельно; настройки — одной записью; список городов — одной записью.
   - Не синхронизируются: включение будильника, пропуск ближайшего срабатывания, будильники перед событиями календаря (они от календаря этого телефона, D-023), отметки о настройке телефона (Xiaomi, первый запуск), идущие таймеры, секундомер, журнал и статистика.
   - Своя картинка фона — файл этого телефона: «картинка» доходит до другого как есть, там видна его картинка, а пока её нет — фона нет.
3. **Слияние** — по записям, с хешем версии.
   - Телефон помнит, на какой версии каждой записи он и файл сошлись в прошлый раз. Поменялась только одна сторона — берётся она, без вопроса.
   - Поменялись обе — расхождение. Пока его не разрешили, в файле — чужая версия, на телефоне — своя.
   - Расхождение показывается плашкой над будильниками и уведомлением. В окне «Синхронизация: выберите версию» у каждой записи — версия этого телефона и другого, с именем телефона и временем правки. Выбранная версия уходит в файл; другой телефон берёт её без вопроса.
   - Удалённое помнится в файле 90 дней, потом забывается. Телефон, который не синхронизировался дольше, вернёт удалённое как новое.
   - Два телефона записали файл одновременно — правка одного может пропасть из файла. Телефон это видит при следующем чтении и записывает правку снова, без вопроса.
4. **Когда.**
   - Через минуту после правки — если среди изменений есть то, что синхронизируется.
   - При открытии приложения — не чаще раза в минуту.
   - Раз в час — задание Android при любой сети.
   - Кнопка «Синхронизировать сейчас».
   - До первой разблокировки телефона синхронизации нет: облако ещё не работает.
5. **Включение своё у телефона.** Правка будильника с другого телефона не включает и не выключает его здесь. Новый будильник с другого телефона приходит выключенным. Звонящий будильник и ждущий «Не спите?» не трогаются — правка ждёт следующего прохода.
6. **Первое подключение.** Новый пустой файл — данные телефона уходят в него. В файле уже есть данные — вопрос:
   - «Объединить» — записи обоих телефонов вместе; одно и то же разное — расхождение, например настройки;
   - «Взять из файла» — свои будильники, группы, шаблоны, исключения, пресеты и города удаляются, настройки — из файла. Будильники календаря остаются.
7. **Хранение.** Файл синхронизации — свой формат JSON (`SyncFormat`, версия 1) с теми же объектами, что в файле переноса. Ссылка на файл и состояние синхронизации — в хранилище устройства, вне резервной копии Android: копия приложения на новом телефоне начинает с выбора файла. Схема базы не меняется.
8. **Ошибки.** Файл не открылся — «проверьте интернет или выберите файл снова». В файле не синхронизация DP Clock — файл не перезаписывается. Записать не удалось — следующий проход запишет снова.

## Аргументы

- Слово автора.
- Один файл работает с Google Диском и с любым облаком, у которого есть поставщик документов.
- Слияние по записям: правки на разных телефонах в разных будильниках не мешают друг другу и не требуют вопросов.

## Последствия

- План проверки — Ф1–Ф8.
- Приватность — `docs/SECURITY/PRIVACY_AND_API_KEYS.md`: данные уходят в файл, который выбрал человек, и в облако, где он лежит.
- Файл обновляется медленно: облако само решает, когда выгрузить и скачать. Мгновенного обмена нет — см. «Пересмотр» D-028.
- Тест применения в базе — на Robolectric, запуск с `-Pscreenshots`.

## Пересмотр

- Облако портит файл при одновременной записи или долго отдаёт старую версию — писать по файлу на телефон, если облако даёт выбрать папку.
- Вопросы о расхождениях мешают — брать свежую правку без вопроса.
- Нужна разная настройка на разных телефонах (например, фон) — сделать её своей у телефона.
