# D-039 — Лицензия GPL-3.0 и выпуски на GitHub

- **Статус:** Accepted — слово автора 12 ноября 2026
- **Дата:** 2026-11-12
- **Область:** лицензия, распространение сборок ([D-005](D-005-DEBUG-BUILDS.md), [D-026](D-026-SCOPE-CUTS.md), п. 4), CI ([D-036](D-036-PROFESSIONAL-FOR-SELF.md), п. 2).

## Контекст

11 ноября 2026 автор сделал репозиторий открытым: «теперь это open source проект». Лицензии в нём не было. 12 ноября автор сказал: «Добавь лицензию GPL-3.0, запусти сборку через GitHub Actions, сборка с описанием должна попасть в Releases».

## Решение

1. **Лицензия — GNU GPL версии 3.** Текст — файл `LICENSE` в корне (дословно, SHA-256 `3972dc97…fb36986`). В приложении — строка в «О приложении».
   - Зависимости совместимы: Apache-2.0 (AndroidX, Compose, Kotlin, ZXing) и BSD 3-Clause (libyuv в CameraX) входят в работу под GPL-3.0; данные tz — общественное достояние; данные MET Norway — CC BY 4.0, в APK не входят.
   - Идеи DP_Repeated_Tasks автора (GPL-3.0, D-033) теперь можно брать и кодом; чужой код по-прежнему не переносится (D-003).
2. **Выпуски — GitHub Releases.** Рабочий процесс `.github/workflows/release.yml`:
   - запускается тегом `v<версия>` или вручную;
   - проверяет, что тег называет версию из `app/build.gradle.kts`, и что есть описание `docs/RELEASE_NOTES/<версия>.md`;
   - гоняет тесты и Lint, собирает APK выпуска и отладочный;
   - создаёт выпуск `v<версия>` с этим описанием, файлами `dp-clock-<версия>.apk` и `dp-clock-<версия>-debug.apk` и их SHA-256; повторный запуск обновляет тот же выпуск.
3. **Ветка `debug-builds` остаётся** для сборок между выпусками (D-005).
4. **Подпись не меняется:** общий отладочный ключ из репозитория, чтобы выпуск ставился поверх прежних сборок. Магазинов по-прежнему нет (D-026).

## Последствия

- Ключ подписи в открытом репозитории: любой может собрать APK, который встанет поверх установленного. По D-005 это условие пересмотра — ключ заменить и вынести в секрет GitHub Actions. Решение за автором; записано в TODO.
- Новая версия для выпуска — это `versionName`, файл описания и тег.

## Пересмотр

- Автор решит сменить ключ — выпуск подписывается ключом из секрета; одна переустановка с переносом данных файлом.
