# Журнал решений

Здесь фиксируются решения, влияющие на архитектуру, безопасность, продуктовую направленность и стоимость дальнейших изменений.

## Правила
- Каждое решение получает постоянный ID и отдельный Markdown-файл.
- Статусы: **Proposed**, **Accepted**, **Superseded**, **Rejected**.
- В решении указываются контекст, варианты, аргументы, последствия и условия пересмотра.
- Принятые решения синхронизируются с README, roadmap и профильными документами.
- Предложение не означает, что функция реализована.

## Открытые решения
1. Матрица устройств шире первого — перед версией 1.0 (стек и SDK — D-004, первое устройство — D-006).
2. Синхронизация устройств — решена: общий файл в облаке, слияние по записям с вопросом о расхождениях (D-030).
3. Таск-менеджеры: выбраны TickTick, Google Tasks и Todoist (D-028); хранение токенов и показ задач — перед реализацией.
4. Фоны и анимации: как создаются и их происхождение (D-007, D-003). Звуки DP_Clock создаются кодом — D-013.
5. Какие UX-идеи стоит адаптировать после исследования рынка и пользователей.

Магазины, провайдеры ИИ и Wear OS сняты с открытых решений — D-026.
