# Roadmap

**Статус:** версия 0.0.0 — собственный каркас с одним экраном, текущим временем в круге ([D-004](../DECISIONS/D-004-STACK-AND-VERSION-0.0.0.md)). Дальше — P0 и остальное из P1.

**MVP** ([D-006](../DECISIONS/D-006-MVP.md)) — этапы P1 и P2 для его состава; **публичная версия 1.0** ([D-007](../DECISIONS/D-007-VERSION-1.0-SCOPE.md)) — MVP и этапы P3–P5.

## P0. Требования и выбор технической основы
**Цель:** принять решения, необходимые для первой реализации.
- [x] Зафиксировать MVP и основные пользовательские сценарии — [D-006](../DECISIONS/D-006-MVP.md).
- [x] Исследовать официальные Android APIs и ограничения критических сценариев времени — [ANDROID_PLATFORM.md](../docs/RESEARCH/ANDROID_PLATFORM.md), [D-008](../DECISIONS/D-008-PLATFORM-MECHANISMS.md) (предложено), план проверки — [DEVICE_TEST_PLAN.md](../docs/QUALITY/DEVICE_TEST_PLAN.md).
- [ ] Изучить похожие приложения как функциональные ориентиры, не копируя код.
- [x] Выбрать язык, build-систему, minSdk/targetSdk и целевые устройства — стек и SDK (D-004), первое устройство — Redmi Note 13, Android 15, HyperOS 2 (D-006).
- [ ] Определить модель данных и карту экранов.
- [ ] Записать значимые решения в DECISIONS.

**Критерий выхода:** выбран стек, описан MVP, известны критические ограничения платформы и способы их тестирования.

## P1. Минимальный работающий каркас
- [ ] Создать Android-проект с application ID и базовой навигацией — проект и `com.dpsmpx.dpclock` есть (версия 0.0.0), навигации нет: один экран.
- [x] Настроить воспроизводимую сборку и автоматические проверки — Gradle wrapper, unit-тесты, Lint.
- [ ] Создать разделы MVP по D-006: «Часы» (экран 0.0.0), «Будильники», «Таймеры», «Секундомер» и настройки; навигация — нижняя панель и свайп; будильники — первыми.
- [x] Задокументировать запуск, сборку и тестирование — `docs/DEVELOPMENT/BUILD.md`.

**Критерий выхода:** приложение устанавливается и запускается на выбранных устройствах.

## P2. Надёжное ядро времени
- [ ] Реализовать модель будильников, повторов и исключений.
- [ ] Реализовать таймеры в соответствии со спецификацией.
- [ ] Обработать перезагрузку, разрешения, Doze, изменение системного времени и временной зоны.
- [ ] Добавить unit- и интеграционные тесты граничных случаев.
- [ ] Проверить фактическое срабатывание на устройствах.

**Критерий выхода:** основные сценарии проходят автоматические проверки и аппаратную приёмку.

## P3. UX, шаблоны и гибкие сценарии
- [ ] Сделать интерфейс простым для базовых действий и расширяемым для сложных.
- [ ] Раздел «Мировые часы» (D-007).
- [ ] Будильник целиком по D-007: название, выбор мелодии, вибрация, нарастание громкости, пропуск одного срабатывания, будильник на дату, интервал «Отложить» у отдельного будильника.
- [ ] Добавить группы/шаблоны будильников.
- [ ] Сменные графики, календарные исключения, подтверждение пробуждения (D-007).
- [ ] Сон и пробуждение: время сна, мягкое пробуждение, ночные часы, действие после будильника (D-007).
- [ ] Варианты на выбор пользователя: вид сигнала, собственные звуки DP_Clock рядом с мелодиями телефона, экспорт и импорт файлом (D-007).
- [ ] Добавить последовательные и параллельные таймерные сценарии — перенесено в MVP (D-006).
- [ ] Добавить настройки пробуждения — «Отложить» и автовыключение сигнала перенесены в MVP (D-006).
- [ ] Оформление: свой цвет темы, стили часов, чёрная тема, размер и начертание цифр, фоны — картинки пользователя, анимации и живые фоны (D-007).
- [ ] Виджеты, плитка быстрых настроек, ярлыки на иконке, команды ассистента и других приложений (D-007).
- [ ] Планшеты и складные телефоны: раскладка для больших экранов (D-007).
- [ ] Проверить доступность, работу одной рукой и ориентации.

**Критерий выхода:** новые функции не нарушают базовые сценарии и покрыты критериями приёмки.

## P4. Интеллектуальный помощник и интеграции
- [ ] Разработать модель типизированных операций.
- [ ] Добавить необязательный API-слой и адаптеры провайдеров.
- [ ] Внедрить проверку, предварительный просмотр, подтверждение и отмену.
- [ ] Внедрить контроль расходов и безопасную работу с ключами.
- [ ] Проверить неоднозначные команды и отказ API.
- [ ] Календарь телефона, чтение задач из таск-менеджеров и действия с ними, синхронизация устройств, локальная статистика — каждое после своего решения о данных и согласии (D-007).
- [ ] Приложение для часов Wear OS (D-007).

**Критерий выхода:** ИИ может только предлагать разрешённые операции; приложение проверяет их самостоятельно; расписания исполняются без сети.

## P5. Подготовка к выпуску
- [ ] Регрессия на поддерживаемых Android и устройствах.
- [ ] Проверки миграций, перезагрузки, разрешений, производительности и энергопотребления.
- [ ] Проверка локализации (русский, английский и другие языки — D-007) и специальных возможностей: TalkBack, крупный шрифт, контраст.
- [ ] Публикация в Google Play и RuStore (D-007).
- [ ] Проверка лицензий реально используемых зависимостей.
- [ ] Документация сборки, установки и ограничений.

**Критерий выхода:** сборка воспроизводима, критические сценарии проверены, ограничения задокументированы.

## Отложенные направления
Синхронизация между устройствами, интеграции и голосовые команды входят в версию 1.0 (D-007), но начинаются только после стабилизации ядра (P2). Сложная автоматизация сверх D-007 — после 1.0.
