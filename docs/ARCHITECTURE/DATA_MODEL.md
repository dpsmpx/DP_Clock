# Модель данных

- **Статус:** модель MVP ([D-006](../../DECISIONS/D-006-MVP.md)) реализована в версии 0.1.0 — `:core:model` и база Room в `:app` ([D-012](../../DECISIONS/D-012-MVP-IMPLEMENTATION.md)); пометки **1.0** — задел под версию 1.0 ([D-007](../../DECISIONS/D-007-VERSION-1.0-SCOPE.md)). Хранение и устройство модулей — [D-009](../../DECISIONS/D-009-DATA-AND-STORAGE.md).
- **Опора:** механизмы платформы — [D-008](../../DECISIONS/D-008-PLATFORM-MECHANISMS.md) и [исследование](../RESEARCH/ANDROID_PLATFORM.md).

Пометка **1.0** у поля или правила — появляется после MVP; в MVP поле может уже существовать со значением по умолчанию, если так дешевле, чем миграция.

## 1. Общие правила

- **Идентификаторы** — UUID строкой. Синхронизация устройств (D-007) потребует их, поэтому заводятся сразу.
- **Время суток будильника** — местное время, час и минута. Оно «плавает» вместе с часовым поясом: 7:00 остаётся 7:00 местного времени после перелёта и после смены пояса в настройках.
- **Моменты** (конец «Отложить», конец таймера, событие в журнале) — абсолютные: миллисекунды UTC. От смены пояса они не меняются.
- **Длительности** (таймер, секундомер) отсчитываются по монотонным часам устройства (`elapsedRealtime`). Рядом хранятся номер загрузки устройства и момент UTC: в той же загрузке используются монотонные часы, они не зависят от перевода времени; после перезагрузки — момент UTC.
- **Правила времени** — чистые функции без Android: вход — правило и «сейчас» с поясом, выход — момент. Покрываются unit-тестами на граничных датах и поясах.

## 2. Будильник (`Alarm`)

| Поле | Тип | MVP | Смысл |
|---|---|---|---|
| `id` | UUID | да | |
| `time` | час, минута | да | местное время сигнала |
| `repeat` | правило повтора | да | см. ниже |
| `enabled` | да/нет | да | |
| `createdAt` | момент | да | порядок в списке при равном времени |
| `label` | текст | 1.0 | название |
| `sound` | ссылка на мелодию или свой звук | 1.0 | в MVP — мелодия будильника телефона по умолчанию |
| `vibrate` | да/нет | 1.0 | в MVP — вибрация со звуком |
| `snoozeMinutes` | число или «общий» | 1.0 | замена общего интервала |
| `rampSeconds` | число | 1.0 | нарастание громкости |
| `skipDate` | дата | 1.0 | пропуск одного срабатывания |
| `groupId` | UUID | 1.0 | группа |
| `wakeCheck` | способ и настойчивость | 1.0 | подтверждение пробуждения |
| `afterAction` | ссылка на пресет таймера или напоминание | 1.0 | действие после будильника |

**Правило повтора** — один из вариантов:
- `Once` — ближайшее наступление времени: сегодня, если ещё впереди, иначе завтра. После срабатывания будильник выключается.
- `Weekly(days)` — дни недели.
- **1.0:** `OnDate(date)` — один раз в указанную дату.
- **1.0:** `Cycle(anchorDate, steps)` — сменный график: цикл из N дней от опорной даты; у каждого дня цикла — своё время или «выходной».

**1.0:** календарные исключения — даты и периоды, в которые будильник или группа не звонят; хранятся отдельной таблицей и учитываются при расчёте.

**Следующее срабатывание** считается от «сейчас» в текущем поясе: первая подходящая дата с временем строго позже «сейчас». Особые случаи:
- **Переход на летнее время** (время пропущено, например 2:30 не наступает) — сигнал в первый существующий момент после пропуска. Лучше разбудить раньше, чем проспать.
- **Переход на зимнее время** (время наступает дважды) — сигнал один раз, в первое наступление.
- **Опоздание больше 10 минут** — телефон был выключен или часы переведены вперёд. Будильник не звонит задним числом: остаётся уведомление «Пропущенный будильник», повторяющийся переходит к следующему срабатыванию.

## 5. Таймеры

**Программа (`TimerProgram`)** — одна и та же модель для одиночного таймера, пресета, цепочки и цикла:

| Поле | Тип | Смысл |
|---|---|---|
| `steps` | список шагов | у шага — длительность, необязательное название, сигнал в конце (короткий или полный) |
| `cycles` | число | сколько раз пройти шаги; 1 — без повтора |

Одиночный таймер — программа из одного шага с полным сигналом.

**Пресет (`TimerPreset`):** `id`, `name`, `program`, `createdAt`; **1.0** — звук.

**Идущий таймер (`TimerRun`)** — каждый запуск; их может быть несколько одновременно:

| Поле | Тип | Смысл |
|---|---|---|
| `id` | UUID | |
| `presetId` | UUID или пусто | откуда запущен |
| `program` | копия программы | правка пресета не меняет идущий таймер |
| `state` | идёт / пауза / звонит / закончен | |
| `stepIndex`, `cycleIndex` | числа | где сейчас |
| `stepEndsAtElapsed`, `bootCount`, `stepEndsAtUtc` | моменты | конец текущего шага, пока идёт |
| `remainingMillis` | число | остаток шага на паузе |

Конец шага — точный будильник (D-008, п. 3). После перезагрузки идущий таймер продолжается от `stepEndsAtUtc`; шаги, закончившиеся, пока телефон был выключен, засчитываются пройденными без сигнала, кроме последнего — по нему уведомление «Таймер закончился».

| Поле | Тип | Смысл |
|---|---|---|
| `id` | UUID | |
| `source` | будильник / таймер | и его `id` |
| `scheduledAt`, `firedAt` | моменты | расчётное и фактическое время |
| `outcome` | выключен / отложен / автовыключение / пропущен | |

Хранятся последние 1000 событий.

## 8. Хранение

- Всё — в одной базе SQLite через Room, в **хранилище устройства**, чтобы будильник прозвонил до первой разблокировки после перезагрузки (D-008, п. 5). Личные данные туда не кладутся.
- Схема версионируется с первого выпуска сборки; каждая версия — миграция с тестом.
- Резервная копия (D-006): база входит в системную копию и перенос на новое устройство; правила `data_extraction_rules.xml` меняются, когда база появится. Идущие таймеры и секундомер после восстановления сбрасываются.
