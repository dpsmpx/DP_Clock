## 1. Общие правила

- **Идентификаторы** — UUID строкой. Синхронизация устройств (D-007) потребует их, поэтому заводятся сразу.
- **Время суток будильника** — местное время, час и минута. Оно «плавает» вместе с часовым поясом: 7:00 остаётся 7:00 местного времени после перелёта и после смены пояса в настройках.
- **Моменты** (конец «Отложить», конец таймера, событие в журнале) — абсолютные: миллисекунды UTC. От смены пояса они не меняются.
- **Длительности** (таймер, секундомер) отсчитываются по монотонным часам устройства (`elapsedRealtime`). Рядом хранятся номер загрузки устройства и момент UTC: в той же загрузке используются монотонные часы, они не зависят от перевода времени; после перезагрузки — момент UTC.
- **Правила времени** — чистые функции без Android: вход — правило и «сейчас» с поясом, выход — момент. Покрываются unit-тестами на граничных датах и поясах.

| `createdAt` | момент | MVP | порядок в списке при равном времени |

| `vibrate` | да/нет | 0.2.0 | по умолчанию — да |
| `snoozeMinutes` | число или «общий» | 0.2.0 | замена общего интервала |

| `honorExceptions` | да/нет | 0.3.0 | не звонить в даты общего списка исключений; по умолчанию — да; только у повторяющегося |

| `gentleMinutes` | число | 0.6.0 | мягкое пробуждение — свет и тихий звук за столько минут; 0 — нет |
| `after` | пресет таймера, напоминание (текст и через сколько минут), приложение | 0.6.0 | действие после выключения человеком |

**Правило повтора** — один из вариантов:
- `Once` — ближайшее наступление времени: сегодня, если ещё впереди, иначе завтра. После срабатывания будильник выключается.
- `Weekly(days)` — дни недели.
- **0.2.0:** `OnDate(date)` — один раз в указанную дату; после срабатывания будильник выключается. Дата прошла — срабатывания нет, будильник выключается.
- **0.3.0:** `Cycle(anchorDate, days)` — сменный график: цикл из 2–28 дней от опорной даты (она может быть в прошлом); у каждого дня цикла — своё время или «выходной», хотя бы один рабочий. Время будильника — время первого рабочего дня цикла.
- **0.3.0:** `Workdays` — рабочие дни по производственному календарю России: будние кроме праздников и переносов, плюс рабочие субботы и воскресенья по переносу.

**0.3.0:** календарные исключения — общий список дат и периодов (таблица `exception_period`) и, если включено в настройках, праздники и переносы России. Будильник с `honorExceptions` не звонит в эти даты; однократный и на дату их не учитывают.

**0.3.0:** группа (`alarm_group`: `id`, `name`, `createdAt`) — общее включение будильников. Шаблон (`alarm_template`: `id`, `name`, будильники строкой, `createdAt`) — набор будильников без id, включения, пропуска и группы; разворачивается в новую группу.

**Следующее срабатывание** считается от «сейчас» в текущем поясе: первая подходящая дата с временем строго позже «сейчас». Особые случаи:
- **Переход на летнее время** (время пропущено, например 2:30 не наступает) — сигнал в первый существующий момент после пропуска. Лучше разбудить раньше, чем проспать.
- **Переход на зимнее время** (время наступает дважды) — сигнал один раз, в первое наступление.
- **Исключения и пропуск** — дата пропускается целиком; поиск идёт до 800 дней вперёд. Не нашлось — у однократного и на дату будильник выключается, у повторяющегося остаётся включённым без срабатывания.
- **Опоздание больше 10 минут** — телефон был выключен или часы переведены вперёд. Будильник не звонит задним числом: остаётся уведомление «Пропущенный будильник», повторяющийся переходит к следующему срабатыванию.

## 5. Таймеры

**Программа (`TimerProgram`)** — одна и та же модель для одиночного таймера, пресета, цепочки и цикла:

| Поле | Тип | Смысл |
|---|---|---|
| `steps` | список шагов | у шага — длительность, необязательное название, сигнал в конце (короткий или полный), **0.5.0** — свой звук или «как у программы» |
| `cycles` | число | сколько раз пройти шаги; 1 — без повтора |
| `sound` | звук | **0.5.0**: звук программы; по умолчанию — мелодия будильника телефона |
| `sleep` | да/нет | **0.5.0**: таймер засыпания — один шаг; в конце без сигнала останавливает музыку и видео |

Одиночный таймер — программа из одного шага с полным сигналом.

**Пресет (`TimerPreset`):** `id`, `name`, `program`, `createdAt`; звук — в программе (**0.5.0**). Программа хранится строкой: `v1` до 0.5.0, `v2` — со звуками и признаком засыпания; `v1` читается.

**Идущий таймер (`TimerRun`)** — каждый запуск; их может быть несколько одновременно:

| Поле | Тип | Смысл |
|---|---|---|
| `id` | UUID | |
| `presetId` | UUID или пусто | откуда запущен |
| `program` | копия программы | правка пресета не меняет идущий таймер |
| `state` | идёт / пауза / звонит / закончен | |
| `stepIndex`, `cycleIndex` | числа | где сейчас |
| `stepEndsAtElapsed`, `bootCount`, `stepEndsAtUtc` | моменты | конец текущего шага, пока идёт |
| `remainingMillis` | число | остаток шага на паузе |

Конец шага — точный будильник (D-008, п. 3). После перезагрузки идущий таймер продолжается от `stepEndsAtUtc`; шаги, закончившиеся, пока телефон был выключен, засчитываются пройденными без сигнала, кроме последнего — по нему уведомление «Таймер закончился».

## 7. Журнал срабатываний (`SignalEvent`)

Только на устройстве; основа будущей статистики (D-007) и проверки на телефоне ([план](../QUALITY/DEVICE_TEST_PLAN.md)): показывает, насколько сигнал опоздал. **0.7.1:** виден в настройках — «Журнал срабатываний», можно поделиться текстом.

| Поле | Тип | Смысл |
|---|---|---|
| `id` | UUID | |
| `source` | будильник / таймер | и его `id` |
| `title` | строка | **0.7.1**: название будильника или таймера на момент записи — запись переживает удаление |
| `scheduledAt`, `firedAt` | моменты | когда этот звонок ожидался и когда зазвучал; **0.7.1**: после «Отложить» ожидался — в конце отложенного, после «Не спите?» без ответа — сразу; у таймера — расчётный конец шага по монотонным часам |
| `outcome` | выключен / отложен / автовыключение / пропущен | |

Записывается звучавший сигнал (**0.7.1**: «Выключить» у отложенного больше не пишется — он уже записан как «Отложен»), пропущенный, ответ на «Не спите?» и «Я уже проснулся». Ожидаемое время звонящего будильника — поле `expectedAt` срабатывания (**0.7.1**). Хранятся последние 1000 событий.

## 8. Хранение

- Всё — в одной базе SQLite через Room, в **хранилище устройства**, чтобы будильник прозвонил до первой разблокировки после перезагрузки (D-008, п. 5). Личные данные туда не кладутся.
- Схема версионируется с первого выпуска сборки; каждая версия — миграция с тестом. Схема 2 — версия 0.2.0, схема 3 — 0.3.0, схема 4 — 0.4.0, схема 5 — 0.6.0, схема 6 — 0.7.1; тест миграций идёт на JVM со встроенным SQLite (D-013, п. 10).
- Резервная копия (D-006): база входит в системную копию и перенос на новое устройство; правила `data_extraction_rules.xml` меняются, когда база появится. Идущие таймеры и секундомер после восстановления сбрасываются.
- **0.7.0** — файл переноса (D-018): `Backup` в `:core:model`, JSON формата 1 (`BackupFormat`) — будильники, группы, шаблоны, исключения, пресеты и настройки без отметки про Xiaomi; идущих таймеров, секундомера, срабатываний и журнала в нём нет. Загруженному даются новые id (`BackupRules.forImport`); ссылки будильников на группы и пресеты файла переводятся, на отсутствующие — снимаются. Схема базы не меняется.
