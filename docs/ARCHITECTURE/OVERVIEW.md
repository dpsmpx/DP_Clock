# Архитектурный обзор DP_Clock

- **Статус:** предварительные целевые границы; реализация пока отсутствует.
- **Подход:** собственная реализация с нуля с опорой на официальные Android APIs.

## Предварительные слои

### 1. Модель времени
Собственные доменные сущности и правила: будильник, повторы и исключения; таймер и его состояния; последовательный/параллельный сценарий таймеров; временная зона; конфликты расписаний и валидация.

Схема определяется реальными пользовательскими сценариями, а не воспроизводится из внутренних моделей другого приложения.

### 2. Операции приложения
Типизированные действия: создать или изменить будильник, сохранить пресет таймера, изменить шаг сценария, проверить конфликт, получить preview, применить или отменить изменение.

UI и ИИ должны использовать одинаковые операции. ИИ не может обходить валидацию или напрямую изменять хранилище.

### 3. Android integration
Собственные адаптеры к официальным Android APIs для планирования событий, уведомлений, звука, обработки перезагрузки и хранения данных. Конкретные механизмы зависят от выбранных версий Android.

### 4. UI / UX
Основные действия доступны без ИИ. Расширенные настройки, шаблоны и таймерные сценарии не должны перегружать базовый интерфейс.

### 5. Необязательный AI layer
Адаптеры провайдеров преобразуют запросы в предложения структурированных операций. Приложение валидирует изменения, показывает preview и при необходимости запрашивает подтверждение.

## Принципы
- local-first для сохранённых расписаний;
- собственная модель данных и бизнес-логика;
- явные границы модели, UI и платформенных APIs;
- валидация до сохранения;
- безопасные миграции;
- минимальные разрешения и сбор данных;
- автоматические тесты для граничных случаев времени.

Язык, библиотеки, архитектурный шаблон и build-система остаются открытыми решениями до уточнения MVP.
