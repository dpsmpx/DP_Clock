# Development Workflow

## Источники истины

- README.md — сводка и навигация.
- TODO.md — только активные незавершённые задачи.
- ROADMAP/ROADMAP.md — этапы и критерии завершения.
- DECISIONS/ — значимые решения и история.
- CHANGELOG.md — заметные изменения.
- docs/ — спецификации и результаты исследований.
- docs/PROVENANCE.md — происхождение заимствованных файлов.

## Перед реализацией

1. Уточнить требование и пользовательский сценарий.
2. Проверить, нет ли уже такой возможности в DP_Clock. Если задача давно решена в AOSP DeskClock, файл можно заимствовать по D-003 и [docs/PROVENANCE.md](../PROVENANCE.md).
3. Описать ожидаемое поведение и граничные случаи.
4. Установить проверку и критерий приёмки.
5. При изменении архитектуры или гарантий создать/обновить решение.

## Во время реализации

- Не смешивать рефакторинг с изменением пользовательского поведения без причины.
- Сохранять понятность базовых сценариев.
- Для правил времени добавлять детерминированные тесты на граничных датах и временных зонах.
- Не считать успешную компиляцию доказательством корректного реального срабатывания.
- Не добавлять API-ключи, персональные данные и приватные конфигурации в Git.

## После изменения

1. Запустить доступные автоматические проверки и записать фактические результаты.
2. Если изменение касается системного срабатывания, протестировать критические сценарии на целевых устройствах.
3. Обновить roadmap, TODO, changelog и решения при необходимости.
4. Обновить README при изменении описания проекта или его статуса.

## Статусы

- **Implemented** — код существует.
- **Tested** — есть конкретный результат проверки с условиями.
- **Planned** — направление включено в план.
- **Proposed** — идея без принятого решения.
- **Blocked** — указана причина, мешающая продвижению.

Функция не считается завершённой только на основании документации или успешного unit-теста.
