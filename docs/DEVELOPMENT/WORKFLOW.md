# Development Workflow

## Источники истины
- README.md — сводка и навигация.
- TODO.md — активные задачи.
- ROADMAP/ROADMAP.md — этапы и критерии.
- DECISIONS/ — значимые решения.
- CHANGELOG.md — заметные изменения.
- docs/ — спецификации и результаты исследований.
- docs/DEVELOPMENT/BUILD.md — сборка, проверки и отладочные APK.
- docs/PROVENANCE.md — происхождение зависимостей.

## Перед реализацией
1. Описать пользовательский сценарий, ожидаемое поведение и крайние случаи.
2. Изучить официальные Android APIs и ограничения целевых версий.
3. При необходимости сравнить сторонние приложения по функциям и UX, не копируя исходный код.
4. Определить критерий приёмки.
5. При изменении архитектуры или безопасности обновить DECISIONS.

## Во время реализации
- DP_Clock создаётся с нуля; чужие исходники не переносятся.
- Не смешивать рефакторинг с изменением поведения без причины.
- Для правил времени писать воспроизводимые тесты, включая граничные даты и временные зоны.
- Успешная компиляция не доказывает корректное реальное срабатывание будильника.
- Не добавлять API-ключи, персональные данные и приватные конфигурации в Git.

## После изменения
1. Запустить доступные проверки (`./gradlew :app:testDebugUnitTest :app:lintDebug`, [сборка](BUILD.md)) и записать фактические результаты.
2. При изменении системного срабатывания проверить сценарии на целевых устройствах.
3. Обновить roadmap, TODO и changelog; обновить решения при необходимости.
4. Обновить README при изменении статуса проекта.

## Статусы
- **Implemented** — код существует.
- **Tested** — есть конкретный результат проверки.
- **Planned** — направление запланировано.
- **Proposed** — идея без принятого решения.
- **Blocked** — указана причина блокировки.

Функция не считается завершённой только по документации или одному unit-тесту.
