# Android Integration: исследование и ограничения

Документ задаёт направления проверки для собственной реализации DP_Clock; он не утверждает поддержку конкретного уровня Android.

## Критические механизмы
- Планирование будильников и поведение точных срабатываний.
- Разрешения на точные будильники и уведомления.
- Действия пользователя из уведомлений.
- Воспроизведение сигнала, вибрация и управление звуком.
- Восстановление после перезагрузки и обновления приложения.
- Doze, фоновые ограничения и энергосбережение производителя.
- Часовые пояса, DST, ручная смена системной даты и времени.
- Полноэкранный интерфейс будильника и его ограничения.
- Локальное хранилище, миграции и восстановление данных.

## Исследование платформы
minSdk 31 (Android 12), targetSdk 37 (Android 17) — [D-004](../../DECISIONS/D-004-STACK-AND-VERSION-0.0.0.md). Для заявленной поддержки:
- изучить официальные Android APIs и изменения по уровням API;
- составить таблицу системных ограничений;
- отделить гарантии Android от особенностей производителя;
- определить эмуляторы и реальные устройства для тестирования; первое устройство — Redmi Note 13, Android 15, HyperOS 2.0.213 ([D-006](../../DECISIONS/D-006-MVP.md));
- выбирать разрешения по правилам Google Play: публикация там — в будущем (D-006).

## Выбранные механизмы

Исследование — [ANDROID_PLATFORM.md](../RESEARCH/ANDROID_PLATFORM.md), решение — [D-008](../../DECISIONS/D-008-PLATFORM-MECHANISMS.md) (предложено до проверки на устройстве), проверка — [DEVICE_TEST_PLAN.md](../QUALITY/DEVICE_TEST_PLAN.md). Кратко:

- будильник — `setAlarmClock()` с `USE_EXACT_ALARM` (на Android 12–12L — `SCHEDULE_EXACT_ALARM`);
- сигнал — уведомление с полноэкранным интентом, служба переднего плана `systemExempted`, звук `USAGE_ALARM`; без разрешения на уведомления сигнала нет;
- таймеры и секундомер — без службы переднего плана, от сохранённых моментов времени; конец таймера — точный будильник;
- перезагрузка — Direct Boot и хранилище устройства; Android 15 отменяет будильники при принудительной остановке;
- HyperOS — только официальные API и подсказки пользователю о настройках.

## Принцип
DP_Clock не зависит от закрытых внутренних API другого приложения. Используются официальные Android APIs либо явно документированные требования к целевой ROM, если такое решение будет принято отдельно.

Нельзя обещать одинаковое поведение на всех прошивках до аппаратной приёмки.
