# Концепция DP_Clock — самостоятельные часы Android

- **Тип:** продуктовая концепция.
- **Статус:** proposal на этапе планирования; описанные функции не реализованы этим документом.
- **Подход:** собственный исходный код с нуля.
- **Функциональные ориентиры:** AOSP DeskClock и другие часы могут изучаться для сравнения функций и UX, но их исходный код не копируется в DP_Clock.

## 1. Продуктовая идея
Создать гибкое, умное и удобное приложение часов для Android: от одного будильника до сложных расписаний, цепочек таймеров и сценариев, которые пользователь задаёт обычным языком.

Предполагаемые базовые разделы: будильники, мировые часы, таймеры и секундомер. Состав MVP — [D-006](../../DECISIONS/D-006-MVP.md): часы, будильники, таймеры и секундомер. Публичная версия 1.0 — [D-007](../../DECISIONS/D-007-VERSION-1.0-SCOPE.md): все разделы, включая мировые часы, и расширения ниже.

## 2. Основные направления

### 2.1. Гибкие расписания
Будильники с повторами, сериями и исключениями; отдельные расписания для работы, выходных, сменного графика, сна и поездок. Редактирование серии по возможности выполняется через общий шаблон.

Нужно определить семантику повторов, временных зон, календарных исключений, изменения системного времени и конфликтов расписаний.

### 2.2. Таймеры как конструктор процессов
Последовательные и параллельные таймеры, именованные пресеты и циклы вроде Pomodoro, интервальных тренировок или подходов с отдыхом. Пример: разминка → упражнение → отдых → следующий подход.

Остановка или перезапуск одного шага не должны неожиданно ломать другие таймеры. Нужна явная модель состояний и переходов.

### 2.3. Настраиваемое пробуждение
Мелодия, вибрация, громкость, нарастание сигнала, откладывание и способы подтверждения пробуждения. Пользователь выбирает настойчивость и поведение будильника.

Доступность этих режимов проверяется на целевых Android-версиях с учётом разрешений и системных ограничений.

### 2.4. Интеллектуальное управление
Пример запроса:

> По будням буди меня в 7:00, по субботам в 9:00. После пробуждения запусти 15-минутный таймер, а затем напомни проверить список дел.

Приложение преобразует запрос в структуру, проверяет повторы и конфликты, показывает результат и при необходимости запрашивает подтверждение. ИИ работает только через типизированные операции; он не выполняет произвольный код и не исполняет сохранённые будильники.

## 3. UX без перегрузки
- **Обычный уровень:** быстро поставить будильник, таймер или секундомер.
- **Расширенный уровень:** повторы, шаблоны, последовательности, группы и дополнительные параметры.
- **Автоматизированный уровень:** сложные расписания, созданные вручную или с помощью ИИ.

Все уровни используют одну модель данных. Настройка, предложенная ИИ, после сохранения остаётся доступной для ручного редактирования.

## 4. Надёжность
Критические случаи: перезагрузка; разрешения и фоновые ограничения; смена временной зоны и DST; ручное изменение даты/времени; особенности производителей; миграция данных и обновления приложения.

Поддержку сценария нельзя заявлять, пока он не проверен в объявленной матрице устройств.

## 5. Собственная реализация и функциональные ориентиры
DP_Clock получает собственную архитектуру, модель данных и исходный код. Существующие приложения допустимо изучать через публичную документацию и наблюдение пользовательского поведения — сравнивать возможности, настройки и сценарии. Не переносить их исходники или ассеты без отдельного анализа прав.

Официальные Android APIs и документация платформы используются для реализации корректного поведения на Android.

## 6. Последовательность
1. Определить MVP и пользовательские сценарии.
2. Исследовать официальные Android APIs и граничные условия будильников.
3. Выбрать технологический стек и minSdk/targetSdk.
4. Создать собственный каркас и собрать его на устройстве.
5. Реализовать и проверить локальное ядро времени.
6. Добавлять шаблоны, составные таймеры и улучшения UX.
7. Добавить необязательный ИИ-слой после стабилизации модели данных.

## 7. Критерий результата
Пользователь быстро выполняет простые действия, настраивает сложные конфигурации без рутины, а ИИ помогает создавать корректные настройки. Уже сохранённые будильники и таймеры исполняются без сети и API нейросети.
