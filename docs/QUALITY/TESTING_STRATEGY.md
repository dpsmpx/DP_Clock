# Стратегия качества и тестирования

- **Статус:** план. Есть unit-тесты на JVM — правила времени в `:core:model` (переходы на летнее и зимнее время, пояса, високосный год, дата, пропуск, цепочки таймеров, перезагрузка, секундомер), звуки DP_Clock и миграции базы со встроенным SQLite (0.2.0) — и Lint — [сборка](../DEVELOPMENT/BUILD.md). Проверок на устройстве ещё нет.
- **Главный риск:** пропущенное или некорректное срабатывание времени.

## 1. Unit-тесты модели времени
Проверять вычисление следующего срабатывания, повторы и исключения, конфликты, состояния таймеров, сериализацию, восстановление, временные зоны и DST. Граничные даты должны быть воспроизводимыми. Модель и правила — [DATA_MODEL.md](../ARCHITECTURE/DATA_MODEL.md); тесты — в модуле `:core:model` на JVM, миграции базы — на JVM со встроенным SQLite (D-009).

## 2. Интеграционные тесты Android
Проверять планирование/отмену событий, перезагрузку, разрешения и их отзыв, уведомления, обновления, миграции, изменение системного времени и временной зоны. Набор тестов должен соответствовать целевым Android-версиям.

## 3. UI-тесты
Основные потоки: создать/изменить/отключить/удалить будильник; создать одноразовый и повторяющийся таймер; сохранить и повторно применить шаблон; исправить конфликт; просмотреть и отменить предложенные ИИ изменения.

## 4. Приёмка на устройствах
Для каждого сценария указывать устройство, прошивку, Android, разрешения и шаги. Проверять фактическое срабатывание для всех сценариев, поддержку которых заявляет проект. План для будильников, таймеров и секундомера — [DEVICE_TEST_PLAN.md](DEVICE_TEST_PLAN.md).

## Критерии качества
- критические сценарии проходят повторяемые проверки;
- нет регрессий в базовых операциях будильника;
- состояние корректно восстанавливается;
- при отсутствии разрешений пользователь получает понятное сообщение;
- критические дефекты на заявленной матрице устройств отсутствуют.

Для релизных тестов фиксировать commit/build, устройство и Android, условия, ожидаемый и фактический результат, логи и ограничения. Пороговые показатели задаются после получения базовых данных.
