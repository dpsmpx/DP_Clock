# Первоначальное исследование DP_Clock

- **Статус:** не выполнено.
- **Цель:** определить требования к самостоятельным Android-часам и лучшие практики.
- **Ограничение:** не использовать исходный код сторонних приложений как основу и не переносить его в DP_Clock.

## 1. Исследование платформы Android
- [ ] Выбрать целевой диапазон Android API levels.
- [ ] Изучить официальные APIs для будильников, уведомлений, фонового выполнения и воспроизведения сигнала.
- [ ] Изучить точные будильники и связанные разрешения по версиям Android.
- [ ] Определить поведение после перезагрузки, изменения времени и временной зоны.
- [ ] Составить таблицу отличий AOSP и vendor ROM для сценариев, которые планируется поддерживать.
- [ ] Зафиксировать ссылки на официальную документацию, версии API и ограничения.

## 2. Функциональные ориентиры
Существующие приложения можно изучать по публичной документации и пользовательскому поведению, чтобы сравнивать сценарии без копирования реализации.
- [ ] Составить матрицу функций стандартных часов Android.
- [ ] Сравнить повторы будильников, исключения и шаблоны.
- [ ] Изучить подходы к последовательным/параллельным таймерам.
- [ ] Сравнить настройки сигнала, откладывания, виджеты и быстрые действия.
- [ ] Записать идеи для проверки в DP_Clock и собственные решения по UX.

## 3. Происхождение кода и ассетов
- Исходный код DP_Clock создаётся самостоятельно.
- Не копировать исходники DeskClock или других приложений в каталог проекта.
- Не переносить изображения, звуки, иконки и другие ассеты без установления происхождения и прав.
- Официальные Android APIs и публичная документация используются для понимания платформенных контрактов.
- До добавления сторонней библиотеки проверить лицензию, происхождение, поддержку и требования к notices.

## 4. Технические решения
- [ ] Сравнить Kotlin/Java и доступные инструменты под задачи MVP.
- [ ] Определить application ID, minSdk и targetSdk.
- [ ] Выбрать локальное хранилище и стратегию миграций.
- [ ] Определить unit-, integration- и device-тестирование.
- [ ] Зафиксировать решение и его обоснование в DECISIONS.

## Формат отчёта
Указывать источник, дату проверки, целевой Android API level, вывод и влияние на DP_Clock. Отделять наблюдения от предположений и принятых решений.
