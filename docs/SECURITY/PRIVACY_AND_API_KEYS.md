# Безопасность, приватность и API-ключи

## Базовый принцип

Часы должны собирать минимум данных. Основные расписания желательно хранить локально, а внешние запросы выполнять только для явно включённых функций.

Расписания будильников и моменты таймеров хранятся в хранилище устройства, доступном до первой разблокировки после перезагрузки, — иначе будильник не прозвонит до ввода PIN ([D-008](../../DECISIONS/D-008-PLATFORM-MECHANISMS.md)). Личные данные туда не кладутся.

## Ключи подписи

- Отладочные сборки подписаны общим ключом `app/debug.keystore` из репозитория (D-005). Это не секрет: он годится только для отладочных сборок.
- Ключ выпуска в репозиторий не попадает.

## Интеграция ИИ

- Не встраивать постоянный секрет разработчика в распространяемый APK.
- При BYOK использовать подходящее для Android защищённое хранение и объяснять последствия пользователю.
- При собственном backend определить аутентификацию, квоты, журналирование и защиту от злоупотреблений.
- Ясно сообщать, какие данные уходят провайдеру, какова стоимость и какие политики хранения применимы.
- Предусмотреть бюджетные лимиты, таймауты и поведение при недоступности API.

## Полномочия ИИ

Модель предлагает действия, но не получает произвольного доступа к shell, файлам или системным APIs. Допустимые изменения ограничиваются типизированными операциями над объектами часов. Приложение самостоятельно проверяет диапазоны, время, повторы, конфликты и разрешения.

Для существенных изменений показывать предварительный просмотр. При неоднозначном запросе предпочтительно уточнение, а не молчаливое предположение. История и отмена полезны там, где их можно реализовать безопасно.

## Приватность

- Не отправлять историю расписаний внешнему сервису без необходимости и согласия.
- Передавать только данные, необходимые для текущей команды.
- Не записывать ключи и лишний личный контекст в диагностические логи.
- Не включать секреты и персональные данные в тестовые фикстуры.
- Документировать экспорт, резервирование, очистку и удаление данных, когда эти функции будут спроектированы.

## Открытые вопросы

BYOK или сервис, оплачиваемый разработчиком; необходимость backend; список провайдеров; механизм безопасного хранения с учётом минимального Android; политика аналитики и crash reports. Эти вопросы должны быть решены до выпуска AI-функций.

Версия 1.0 ([D-007](../../DECISIONS/D-007-VERSION-1.0-SCOPE.md)) добавляет доступ к календарю, таск-менеджерам и синхронизацию устройств. До реализации каждой: какие данные читаются и куда уходят, как получается согласие пользователя и как его отозвать.
